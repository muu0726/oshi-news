# 開発指示書：Webアプリケーション「推しニュース」のプロトタイプ構築

## 1. 概要
登録した人物（アイドル・インフルエンサー等）ごとにタブが生成され、毎朝その人物に関する最新ニュースを自動集約・AI要約して閲覧できるWebアプリケーション「推しニュース」を開発します。
将来的にExpo（React Native）を用いたスマートフォンアプリ（iOS / Android）への移植およびバックエンド（Supabase）の共有を前提とした設計にします。

---

## 2. 技術スタック
- **Front-end:** Next.js (App Router, TypeScript, Tailwind CSS)
- **UI Components:** shadcn/ui または Lucide Icons (スマートフォン操作を意識したUI/UX)
- **Back-end / Database:** Supabase (Auth, Postgres DB, Edge Functions)
- **AI Processing:** Gemini API (`gemini-2.5-flash` または `gemini-3.1-flash-lite`)
- **Automation / Cron:** GitHub Actions または Supabase Cron (毎朝のバッチ実行用)

---

## 3. 主要機能要件とユーザーフロー

### (1) ユーザー管理
- Supabase Authを使用したユーザー登録・ログイン機能。

### (2) 人物登録機能（パターンA：Geminiによる人物同定・候補選択）
同姓同名やノイズを排除し、確実に本人を特定・登録するためのフローを実装します。
1. **検索入力:** ユーザーが人物名を入力して「検索」を実行。
2. **候補取得:** Gemini API（`gemini-2.5-flash`）を呼び出し、入力された名前から想定される実在の人物・インフルエンサー・アイドル等を最大5件リストアップ（JSON形式で取得）。
3. **候補提示 UI:** 各候補のカード（名前、肩書/所属グループ、簡単な説明）をリスト表示。
4. **登録確定:** ユーザーが該当する人物を選択すると、以下のメタデータを含めてSupabaseの`favorites`テーブルに保存。
   - 表示名（`name`）
   - 肩書・所属（`category_or_group`）
   - ノイズカット用キーワード（識別用固有情報）
   - 表記揺れキーワード（愛称、アルファベット表記等）

### (3) ダッシュボード（メイン画面）UI
- 上部（モバイル表示時は上部またはスワイプタブ）に登録人物ごとのタブを動的に生成。
- タブ切り替えで、該当人物の最新ニュース一覧を表示。
- **ニュースカードの構成:**
  - ニュースタイトル
  - 出典メディア名 ＆ 発行日時
  - AIによる「3行要約」
  - 元記事への外部リンクボタン（In-App Browser または 外部タブで開く）

### (4) バックエンド：毎朝のニュース自動取得 ＆ AIパイプライン
- **実行タイミング:** 毎朝 5:00（Cronバッチ処理）
- **処理フロー:**
  1. 登録されている全人物およびそのメタデータ（所属・表記揺れキーワード）をDBから取得。
  2. RSSフィードやニュース検索API等から最新ニュース（過去24時間以内）を取得。
  3. **Gemini APIによる同姓同名判定・フィルタリング:**
     - 登録時のメタデータをもとに「この記事が間違いなく本人に関するニュースか」を判定し、無関係な同姓同名ニュースを自動除去。
  4. **AI要約:** 本人のニュースである場合、記事内容から最大3行の要約を生成。
  5. 判定・要約済みのデータをSupabaseの`news`テーブルへ保存。

## 4. データモデル設計（Supabase Schema イメージ）

### `users` テーブル
- `id` (UUID, Primary Key)
- `email` (Text)
- `created_at` (Timestamp)

### `favorites` テーブル（登録された推し）
- `id` (UUID, Primary Key)
- `user_id` (UUID, Foreign Key -> users.id)
- `name` (Text) - 表示名
- `category_or_group` (Text) - 肩書・所属グループ等
- `keywords` (Text[]) - ノイズカット・表記揺れ用キーワード配列
- `created_at` (Timestamp)

### `news` テーブル（収集・要約済みニュース）
- `id` (UUID, Primary Key)
- `favorite_id` (UUID, Foreign Key -> favorites.id)
- `title` (Text) - 記事タイトル
- `url` (Text) - 元記事URL
- `source` (Text) - 出典メディア名
- `summary` (Text) - AIによる3行要約
- `published_at` (Timestamp) - 発行日時
- `created_at` (Timestamp)

## 5. 将来のアプリ化（Expo移植）を見据えたアーキテクチャ設計原則
- **ロジックの分離:** API処理やDB操作（ニュース取得・Gemini連携・Supabaseクエリ）はNext.jsのServer Actionsに強く密結合させず、再利用可能なカスタムフック（React Hooks）やSupabase Client / Edge Functions側に集約してください。
- **UIレスポンシブ:** スマホ表示を意識し、横スワイプによるタブ切り替えやボトムナビゲーションを想定したレスポンシブデザインにしてください。
